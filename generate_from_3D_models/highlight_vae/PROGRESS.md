# highlight_vae 實驗進度紀錄（即時更新）

實驗目標：用與 highlight_diffusion 相同的輸入組合（source 髮型 latent、初始 mask、flow field、cell / strand
overlap graph），改為 **fine-tune strand VAE**（不使用先前訓練的 diffusion model），同時調整髮型與 mask。

時間為 2026-10-26～27（CST）。最新的在最下面。

## 指標說明

所有分數都在每個髮型固定的 20k 髮絲子集上、以 32×32 scalp grid 計算（`highlight_diffusion/reward.py`
的 Scorer，與 `mask_analysis.cal_grid_score` 逐格完全一致）。

| 指標 | 定義 | 單位 / 範圍 | 方向 |
|---|---|---|---|
| grid score（單格） | 該格 column 內挑染髮絲與底色髮絲投影點的凸包重疊：(A₁+A₂−A∪)/A∪；任一色 ≤ 2 根則為 0 | 無因次，[0, 1] | 越低越好 |
| **avg grid score**（`mean_all`） | 32×32 = 1,024 格 grid score 的平均（含沒有頭髮的格，值為 0） | 無因次，[0, 1] | 越低越好 |
| per_black_area | 所有格 grid score 總和 ÷ 黑格數（黑格 = 穿過該 column 的可見髮絲中挑染佔多數） | 無因次，≥ 0，無上限 | 越低越好 |
| per_white_area | 同上 ÷ 白格數（有髮絲穿過、非黑格） | 無因次，≥ 0 | 越低越好 |
| **目標 obj** | max(per_black_area, per_white_area)（gen_dataset filter 的 b 項）；挑染面積較小，實際幾乎都等於 per_black_area；黑格很少時會變得很大，所以同時看中位數 | 無因次，≥ 0 | 越低越好 |
| 翻轉比例 | 標籤與初始 mask 不同的髮絲比例 | 比例，[0, 1] | 參考（FM 約 0.14） |
| 翻轉 F1 | 預測翻轉 vs FM 翻轉的 F1 | [0, 1] | 越高越像 FM |
| 與 FM 一致率 | 標籤與 FM 結果相同的髮絲比例（不改 = 0.898） | [0, 1] | 越高越像 FM |
| 面積變化 | \|挑染髮絲比例 − 初始比例\| ÷ 初始比例 | 相對值（0.3 = 30 %） | 越低越好 |
| 髮絲位移 | 同一髮根解碼前後，每根髮絲 256 個點平均距離的平均 | mm | 越低越好 |
| reward | −[min(obj, 10) + 1.0·面積變化 + 0.05·max(0, 位移 − 1 mm)] | 無因次 | 越高越好 |
| 勝率 | obj 比輸入低（容許 0.1 % 數值誤差）的案例比例 | [0, 1] | 越高越好 |

驗證集（24 例，來自 42 個從訓練髮型切出、從未訓練過的髮型）的平均值易被個別案例拉動，表格以中位數為主。

## 1. 文獻與設計決定

| 問題 | 決定 | 依據 |
|---|---|---|
| VAE decoder 如何接條件 | FiLM 放在 SIREN 的 sine 內：sin(ω(Wh+b)(1+γ)+β)，γ/β zero-init | pi-GAN（Chan et al., CVPR 2021）：對 sine 網路 concat latent 效果差，FiLM 是標準作法；3D-GIF 等沿用 |
| VAE 沒有 transformer | 加入 strand↔cell 二部圖 transformer：strand token 依髮根格與「穿過的 column」平均到 32×32 cell token → 4 層 TransformerEncoder（d=256）→ 再依同樣關係送回 strand | 「若 VAE 不含 transformer 可自行加入幾層」；cell 層級 1024 token 可做全域 attention |
| mask 特徵輸入 | 每根髮絲的 label embedding（如 SAM 的 dense mask embedding / BERT segment embedding 加到 token 上）+ sgraph 交錯特徵 + cell 的 flow / graph 特徵 | 前一實驗結論：目標函數對單根髮絲極敏感，需 strand 解析度 |
| 訓練 | (1) SFT：per-strand BCE 對 FM-on-decoded 的翻轉；(2) reward backprop（DRaFT / AlignProp 式）：可微 surrogate = FM 的 column-rule clique cut（mask 用硬 membership、髮型用 soft membership 讓梯度進 dz / FiLM / decoder）；(3) GRPO：真實 reward，Bernoulli 翻轉 + Gaussian dz 的精確 log-prob | 輸出是 per-strand 離散 / 連續變數，log-prob 可精確計算，GRPO 適用；surrogate 可微時 backprop 比 REINFORCE 樣本效率高 |
| 驗證集 | 從**訓練髮型**切 10%（seed 1，42 個髮型、425 例），完全不碰測試集 | 修正前一實驗的驗證集洩漏 |

## 2. 程式

- `features.py`：per-strand 89 維特徵 + column membership M（cells × S）。
- `model.py`：`Editor`（上述 transformer + 三個 zero-init head：翻轉 logit、dz、FiLM）與 `FilmDecoder`。
  檢查：FiLM=0 時與原 decoder 輸出完全相同（max diff 0.0）。
- `train.py`：`--stage sft | bp | grpo`。三個 stage 的 3 步 smoke test 均通過。
- `evaluate.py`：在 highlight_diffusion 的 124 個測試案例上評估，baseline 列直接沿用（同子集、同 scorer）。
- `val_ckpt.py`：對已存的 checkpoint 重跑驗證（用來補算後來才加入的指標）。
- （使用者要求後加入）驗證輸出加入 avg grid score（模型 / 輸入 / FM 的平均與中位數）與 per_black / per_white。
  SFT 與 bp1 開始時還沒有這個欄位，其 checkpoint 的數值由 `val_ckpt.py` 補算，見各節。

## 9. GRPO 結論（手動在第 200 步停止）

reward −0.644 → −0.833；面積變化不變（約 0.11），髮絲位移上升（3.0 → 3.5 mm）。`best.pt` 仍是第 0 步
（= bp1）。可能原因：每根髮絲獨立的 Bernoulli 探索在 2 萬根上加總，log-prob 的梯度雜訊大，且隨機翻轉
多半是有害的鹽椒狀翻轉，組內 8 個樣本的 reward 差異主要來自雜訊；每步只有 2 個 prompt × 8 個樣本。
**最佳 VAE 模型 = bp1/best.pt（reward backprop）**；GRPO 不再繼續。

## 11. 發現：reward backprop 會「把髮絲豎起來」（reward hacking）

bp2 的渲染（`data/report/hl_1000__case_0193.jpg`、`hl_1000__case_0167.jpg`）顯示：挑染位置確實保留了，但方法是
讓那一束挑染髮絲**沿頭皮法向直直豎起**，離開周圍髮絲。bp1 也有同樣現象，只是較少（case_0167 兩側有豎起的
黑色髮絲）。原因：grid score / clique cut 只看 column 內有沒有異色交錯，一根髮絲豎起後只穿過自己髮根那一格，
就不再和任何髮絲交錯；而位移懲罰是「所有 20k 根髮絲平均位移」（3.0–3.5 mm），少數髮絲移動數公分被平均掉了。

影響：第 7 節與 bp2 測試集表中 vae_bp / vae_bp2（以及 +FM）的數值，部分來自這種不自然的髮型，不能直接當成
「比 FM 好」。需要能偵測它的指標與能防止它的 loss。

對策（bp3）：
- 新指標：每根髮絲平均位移的 p99（mm）、位移 > 10 mm 的髮絲比例；加入驗證與測試評估。
- 新 loss：per-strand 超線性位移懲罰 w · mean_s(relu(d_s − 2 mm)²)，d_s = 第 s 根髮絲的平均點位移（mm），
  讓少數髮絲大幅移動的代價變高；保留 bp2 的翻轉懲罰。
- 已停止原本排在後面的訓練集評估（bp3 需要整張 GPU），之後對最終模型重跑。

量測（`val_ckpt.py`，24 例驗證）：

## 14. 目前結論（2026-10-27）

| | diffusion（前一實驗） | VAE editor（本實驗，bp3） |
|---|---|---|
| 單獨使用，測試集 obj 中位數 | 1.647（輸入 1.658） | **0.603** |
| 單獨使用，avg grid score 平均 | 0.129（輸入 0.125） | **0.062** |
| 勝輸入 | 53 % | **99 %** |
| + FM，obj 平均 / 中位數 / avg grid score | 0.397 / 0.254 / 0.0244 | **0.349 / 0.242 / 0.0221** |
| 平均位移 / p99 | 5.2 mm / – | **2.2 mm / 7.8 mm** |
| 挑染位置 | 幾乎不改 mask | 保留原位置（翻轉 6.8 %） |

- 最佳實作：strand↔cell transformer + FiLM-SIREN decoder fine-tune，SFT（FM 翻轉）→ reward backprop
  （可微 clique cut + 面積 + per-strand 超線性位移 + 翻轉懲罰）。GRPO 在此設定下沒有幫助。
- 單獨使用仍不如 FM（0.603 vs 0.263），但改動小得多（翻轉 6.8 % vs 13.7 %），且保留挑染位置；
  與 FM 串接時三個指標都優於 FM 單獨。
- 教訓：只用「平均位移」限制髮型會被 reward hacking（少數髮絲豎起），必須看 per-strand 的尾部並懲罰。

## 17. 風格 fine-tune 設計（bp4 / bp5）

- **訓練 prompt**：`gen_style_masks.py` 在**訓練**髮型（mid/long，排除驗證髮型）的解碼髮型上，用
  `initial_masks_generation` 原封不動的 `chunky`（每髮型 2 個）與 `money_piece_gc`（1 個）產生 mask，並存每根
  髮絲的條紋 id（chunky 用產生器的 bands，money piece 用連通分量）。120 個髮型，每個約 6 s（20k 髮絲）。
  另對 42 個驗證髮型產生一份作為風格驗證集（`style_masks_val/`），訓練中每次驗證都算條紋保留 / gs / 位移尾部。
- **新 loss**（皆可微，加在 bp 上）：
  - 條紋保留：每條條紋 k 的初始挑染髮絲的平均軟標籤 r_k，`w_keep · mean_k relu(τ − r_k)²`（τ = 0.7）：
    懲罰條紋被吃掉 / 面積極端縮小。
  - 合併懲罰：兩條條紋之間（同時在兩條 2 格內）的底色髮絲的平均軟標籤，`w_gap · mean(y_gap)`：懲罰色塊合併。
  - 面積：沿用全域相對面積變化²；加上條紋保留即涵蓋「面積極端改變」。
  - **DiffLocks 官方 strand-VAE loss** 作為髮型一致性項：`0.5·L1(pos) + 1.0·L1(dir·256) + 20·L1(curv·256)`
    （`NCKU_3D_hair_reconstruction/losses/losses.py`，公尺單位），對每根被編輯的髮絲與其原始髮絲（相對髮根）計算；
    取 mean + mean(l²)/scale，避免少數髮絲大幅變形被平均掉；保留 bp3 的 per-strand 位移懲罰。
- **架構（選用 `--rot`）**：每根髮絲加一個繞髮根的剛體旋轉（axis-angle，≤ 0.3 rad，zero-init），讓 model 能把整根
  髮絲「梳」到旁邊而不改變形狀，直接以移動髮絲來適配 mask（使用者提到的「部分調整髮型來適配 mask」）。
- 兩個 run：bp4 = 新 loss（無旋轉）、bp5 = 新 loss + 旋轉，皆從 bp3 出發。

風格驗證集：42 個驗證髮型中 27 個（mid/long）產生 81 個 mask，訓練中固定取 16 個 chunky（46 條）+ 8 個
money piece（10 個 piece）。

第一次啟動 bp4 時 DiffLocks loss 權重 20 太大（`dl` ≈ 1.9 → 38，遠大於 cut ≈ 0.6），會把髮型直接拉回原樣，
25 步後停止，改用 `--w_dl 0.5` 重跑。另外 smoke test 中旋轉頭 2 步就讓 9 % 髮絲移動 > 1 cm（0.3 rad 對 30 cm
髮絲是 9 cm），旋轉上限改為 0.15 rad。

# 第三部分：密集 chunky（每側 5–10+ 條）與更低的 grid score（2026-10-27）

使用者：實際的 chunky 單側就有 5–10 條以上的紋路，請調整 mask generation；grid score > 0.1 通常代表色塊邊界
混在一起、視覺效果差，請在盡量保留髮型與色塊結構下再降低 grid score，可以放寬 regularization、允許較大的頭髮變形。

## 27. 密集 chunky 產生器（`initial_masks_generation/dense_chunky.py`）

- 原 `chunky` 只有 2–6 條；32×32 grid 一格約 1.2 cm，若條紋以格子為單位（1 格寬 + 1 格間隔），單側最多 5–6 條。
  所以新產生器把條紋定義在**髮絲層級**：一條條紋 = 髮根到某條髮流線（在格子中心之間做雙線性內插，次格精度）
  的 3D 距離 ≤ w/2 的髮絲，w ∈ [6, 9] mm。
- 候選線沿用 `Chunky.lock_table`（從分線與更密的 2 格 lattice 出發、沿有向髮流往下游追的 streamline），每側
  （依條紋垂掛處的方位角）目標 5–10 條，挑選時：可見度高 / 單獨 grid score 低的優先（加 Gumbel 隨機）、與已選條紋
  的線距 < 1.4 cm 的長度比例 ≤ 30 %（平行、不合併）、垂掛方位角相差 ≥ 0.05 rad、髮絲不重複、挑染比例 ≤ 35 %。
- 輸出：每根髮絲的標籤與條紋 id，以及給 grid mask 使用者的髮根格多數決 mask（會失去次格條紋）。
- 整條管線（features、訓練、驗證、評估、FM baseline）改成接受每根髮絲的初始標籤；FM 從髮絲層級的初始狀態
  出發（`train.fm_from_state`）。
- 試產 3 個髮型：每側 5–9 條（目標值都達成），挑染比例 0.15–0.19；渲染（`data/dense_test/overview.jpg`）在背面
  與兩側呈現許多平行細條紋，比原本 2–6 條更接近實際的 chunky，部分條紋被上層頭髮蓋住。
- 資料：測試 = 12 個 hl_n50 測試髮型 × 2 = 24 個 mask（每個 11–17 條）；驗證 = 27 個驗證髮型 × 2 = 54；
  訓練 = 120 個訓練髮型 × 2 = 240（完成，每個 11–17 條）。

## 30. 診斷：為什麼密集 chunky 的 gs 降不下來（`data/eval/dense/`，12–24 個測試 mask，原始頭髮）

grid score 每格 = 挑染點與 base 點在格子切平面投影的凸包重疊（交集 / 聯集）。

| 實驗 | gs | 說明 |
|---|---|---|
| 每根髮絲的細條紋（輸入） | 0.329 | |
| 同一 mask 改成整格（髮根格多數決） | 0.309 | 條紋對齊格子幾乎沒幫助 → 不是「次格寬度」的問題 |
| 同一條紋在 64×64 grid 上算 | 0.296 | 解析度加倍也只降一點 |

→ 主因是長髮：每條條紋的髮絲往下垂時會散開，經過下方許多 column，與那些 column 的 base 髮絲交錯（投影後疊在一起）。
條紋越多，邊界越長，gs 越高（原 chunky 2–6 條 0.221，密集 11–17 條 0.34）。

**只改標籤的極限**（FM 從每根髮絲的初始狀態出發，lam 越大越接近初始 mask；12 個測試 mask，179 條條紋）：

| FM lam | 1e3（預設） | 5e3 | 2e4 | 3.5e4 | 5e4 | 8e4 | 1.5e5 |
|---|---|---|---|---|---|---|---|
| gs | 0.025 | 0.027 | 0.055 | 0.098 | 0.144 | 0.221 | 0.275 |
| kept | 45 | 49 | 63 | 88 | 110 | 138 | 157 |

→ 標籤的取捨很陡：gs < 0.1 時只剩約一半條紋。bp8 的頭髮（位移 p99 ≈ 5 mm）再接 FM 幾乎一樣（lam 5e4：0.128 / 100 條）。

**分析式「條紋成束」（`clump.py`）**：每根挑染髮絲往同條紋、髮根 R 內鄰居的平均曲線拉（權重從髮根 0 線性升到
15 % 長度處的 alpha，髮根不動），base 髮絲不動。凸包重疊只看面積，束緊的條紋在每個 column 的凸包小 → 重疊小，
而 chunky 本來就是一束一束的。

| 成束（R, alpha） | gs | 挑染髮絲位移 mean / p99 (mm) | + FM lam 3.5e4 | + FM lam 5e4 | + FM lam 8e4 |
|---|---|---|---|---|---|
| 不成束 | 0.345 | 0 / 0 | 0.098（88 條） | 0.144（110） | 0.221（138） |
| 2 cm, 0.9 | 0.241 | 7.8 / 30.6 | 0.073（90） | 0.102（112） | 0.156（137） |
| 4 cm, 0.9 | 0.200 | 11.4 / 43.3 | 0.065（89） | **0.087（108），8/12 < 0.1** | 0.135（139） |

→ 成束 + 保留風格的 FM（lam 5e4）在保留同樣條紋數下把 gs 從 0.144 降到 0.087。代價：挑染髮絲平均移動約 1 cm
（只動挑染、髮根不動，base 頭髮不變）。

## 33. 第三部分結論

1. 密集 chunky 產生器（§27）達成每側 5–10 條（測試 11–17 條／頭）。
2. 在 32×32 凸包 grid score 下，**「每側 5–10 條可見細條紋」與「gs < 0.1」本質上衝突**：主要原因不是條紋比格子窄
   （改成整格或 64×64 都只降一點），而是長髮下垂時，每條條紋都會穿過許多 column，和 base 頭髮在投影中交錯；
   條紋越多、邊界越長，gs 越高。只改標籤的取捨很陡（gs < 0.1 時約剩一半條紋，且視覺上合併成色塊）。
3. 放寬 regularization（bp9）讓頭髮動得更多（平均 6–7 mm），但 gs 幾乎沒降：模型的代理目標沒有指出有效的變形方向。
4. 有效的變形方向是**條紋成束**（凸包重疊只看面積，束緊的條紋凸包小）：分析式成束 + 保留風格的 FM（lam 5e4）
   在測試集得到 gs 0.089（15/24 < 0.1），FM 5e4 單獨是 0.138。模型學成束（bp11）沒有成功。
5. 目前建議：
   - 要 gs < 0.1：`clump.py`（R 4 cm, alpha 0.9）+ FM lam 5e4（`style_eval.py --clump_R 0.04 --fm --fm_lam 50000`），
     得到的是幾個乾淨的粗髮束而非細條紋。
   - 要保留密集細條紋外觀：bp8 @500（322/350 條、髮型自然），但 gs ≈ 0.30。
   - 若要兩者兼得，可能需要改評估方式（例如只計可見外層、或依深度加權的 `overlap="projection_depth"`），
     因為內層被蓋住的條紋邊界在視覺上看不到卻仍計入 gs。

# 第四部分：讓 VAE 編輯考慮鄰近髮絲（2026-10-28）

使用者提供的建議：(1) 先做上限測試；(2) 擬合不到才改成「沿長度平滑旋轉方向」或「可學參數的 clump 運算子」，
搭配曲率保持、encoder 重建一致性、頭部 SDF；(3) 需要更一般的協調變形時再用 guide / 體積場。

## 34. 上限測試：固定 decoder，直接對每根髮絲最佳化去擬合成束目標

6 個密集測試 mask，挑染髮絲（每個 ~3000 根）對 §30 的分析式成束目標（4 cm, 0.9）最佳化 400 步（Adam），
decoder 用預訓練權重、不更新。目標平均需要移動 12.3 mm。

| 參數化 | 每根參數 | 擬合誤差 mean / p99 (mm) | gs | + FM lam 5e4 gs |
|---|---|---|---|---|
| 剛體旋轉（現有 rot，≤ 0.15 rad） | 3 | 9.05 / 40.4 | 0.301 | 0.092 |
| 沿長度平滑旋轉方向（5 個 Bernstein 基底 × 3） | 15 | 5.10 / 15.8 | 0.267 | 0.093 |
| **latent dz + FiLM（現有 editor 的輸出）** | 832 | **0.20 / 0.68** | **0.203** | **0.075** |
| 兩者一起 | 847 | 0.19 / 0.92 | 0.203 | 0.076 |

→ **decoder 本身完全表達得出成束後的髮絲**（誤差 0.2 mm，比 decoder 自己的重建誤差 0.87 mm 還小），所以 bp11 的失敗
在 editor 的學習：editor 只透過 1.2 cm 的 cell token 看到鄰居，不知道「同條紋的鄰居在哪裡」，無法為每根髮絲算出
往鄰居收攏的方向。平滑旋轉場做不到收攏（相鄰髮絲要往不同方向轉），單獨用不夠。

## 35. 新架構：耦合內建在結構裡（`model.py`、`clump.py`、`sdf.py`、`train.py`）

1. **鄰居資訊輸入**：每根挑染髮絲的「同條紋鄰居平均曲線 − 自己」（髮根半徑 4 cm 內），取 4 個點、轉到髮根座標系，
   經 MLP 加進 strand token（zero-init）。沒有條紋 id 時，用挑染髮根以 4 mm 連通的元件代替（與真實條紋數最接近）。
2. **可學參數的 clump 運算子**：pos' = pos + β_s · ramp(t) · Δ_s，Δ_s = 鄰居平均 − 自己，ramp 從髮根 0 升到 15 % 長度處的 1，
   β_s = sigmoid(head(h_s)) ∈ [0, 1] 只給挑染髮絲（初始 0.02）。收攏由運算子保證，模型只決定每根收多少。
3. **沿長度平滑旋轉方向**（guide 插值）：dir'(t) = R(t) dir(t)，R(t) = exp(Σ_i B_i(t) c_i)，B_i 為 5 次 Bernstein（B(0) = 0，
   髮根不動，段長不變）；c 由 cell token 預測（guide），以髮根附近 3×3 格的高斯權重插值到每根髮絲，再加小的逐根殘差，
   相鄰髮絲自然得到相近的變形；角度上限 0.8 rad。
4. **正則化**：
   - 局部形狀：曲率大小與段長的 L1（DiffLocks 的縮放），和原始髮絲比，不比位置；
   - encoder 重建一致性：relu(‖D(E(x')) − x'‖ − ‖D(E(x)) − x‖)（mm），用沒用到的 strand-VAE encoder 判斷「像不像 DiffLocks 髮絲」；
   - 身體 SDF：smplx_base.ply 的 signed distance（winding number，4 mm 格點），懲罰比原始更深地穿進身體；
   - 位移平方懲罰只對 base 髮絲（`--hair_sq_base_only`），挑染髮絲靠上面三項約束；
   - compactness：挑染髮絲到「完全成束」曲線的距離（w_cmp 0.05），提供收攏的訊號。

使用者：請把模型輸入輸出、訓練資料等所有解析度都改為 96 後重新跑訓練。

**做法：一個環境變數 `HL_GRID_N=96`，整條管線都改用 96×96**

- `common.GRID_N` 從 `HL_GRID_N` 讀取；預設仍是 32，所以舊實驗不受影響。
- **髮根格子**：`strands.npz` 的 `grid_rc` 是在 32 上算的，所以在 96 上用 `raw_uv` 重新分格。
  - 96 的格子剛好以 3×3 嵌在 32 的格子裡，抽查一個髮型 100 % 吻合。
- **mask / 訓練資料**：存成 32×32 的 mask，以最近鄰上採樣到 96（`common.fit_mask`）。
  - 因為格子是精確巢狀，每根髮絲的標籤完全不變，所以是無損的。
  - 密集 chunky 本來就是每根髮絲的標籤。
- **模型輸入**：
  - 32 時就有的輸入全部改成在 96 上算：column membership、髮絲重疊圖特徵、cell 重疊圖的 RWPE / 度數 / 交叉比例、流場（flux、平均方向）、旋轉場的 guide 插值。
  - membership 改成 sparse COO（每個髮型約 77 萬個非零）。
  - cell 耦合圖 W = N Nᵀ 在 96 上是 9216²，不存 dense，改存 sparse 的 N 與 RWPE / 度數（`extras._graph_sparse`）；交叉比例用 N(Nᵀx) 計算。
  - flow / graph 的快取檔名加上 `_n96`。
- **模型**：cell transformer 有 9216 個 token（4 層全域 attention，PyTorch 的 memory-efficient SDPA）。
  - 從 bp8 @500 初始化時，32×32 的 cell 位置 embedding 以雙線性內插到 96×96。
- **輸出 / 目標 / 評分**：
  - 訓練目標的 clique cut、hair cut（soft membership）、驗證與測試的 grid score、FM 全部在 96 上。
  - merge 懲罰的鄰域（2 格）依格子比例放大成 6 格，物理距離不變。
- 唯一沒改的解析度：DiffLocks 的 scalp texture（256×256 latent）與 strand VAE，它們是髮絲的表示，不是 mask 的 grid。
- 單一 case 前向加反向的峰值為 6.4 GB。
- 訓練約 21 s/step（96 目標、32 輸入的 bp13 是 9.3 s，全 32 的 bp12b 是 2.8 s）。
  - 主要花在 9216-token 的 transformer：每個 case 都要跑訓練模型與 KL 參考模型各一次。
  - 前期還要第一次建立每個髮型的 96 快取。
- 訓練設定與 bp12b / bp13 相同（從 bp8 @500，1000 步，驗證 FM lam 1e5）。

  - 模型用 bp12b（全 32，最快）。
  - 評分與 FM 用 96（捲髮不併塊）。

## 43. 髮絲 kNN attention（bp15）

使用者：加 strand-kNN attention block 進 Editor，並訓練看看。

**動機**：§42 顯示格子解析度提高沒有幫助，因為 cell token 把同一格的髮絲平均掉了，模型看不到「哪根髮絲與哪根髮絲相鄰／交叉」。
文獻上把 attention 加進已訓練網路的常見作法是插入 residual block、輸出層 zero-init（Non-local Networks、SAGAN γ=0、
ControlNet zero conv），而不是蒸餾或重訓。點雲的鄰接多用 kNN local attention（DGCNN、Point Transformer）。

**做法**（`--knn_layers 2 --knn_k 8 --knn_k_mid 8 --lr_knn 3e-4`；預設關閉，關閉時與舊模型相同）
- `model.StrandKNNBlock`：pre-norm 的多頭 local attention + FFN，放在 cell transformer 回到髮絲（`h`）之後、各 head 之前。
  - 每根髮絲只對自己的 K = 16 個鄰居做 attention。
  - 相對幾何照 Point Transformer v1：δ_ij = MLP(rel_ij) 加到 key 與 value。
  - 輸出投影與 FFN 最後一層 zero-init：載入舊 checkpoint 時輸出不變（實測與同一模型跑兩次的 GPU 雜訊同為 3e-6）。
  - backward 用 gradient checkpointing（每個 case 約多 1.5 GB）。
- `features.Static.knn`：鄰居取自解碼後的原始頭髮，每個髮型快取一次（0.2 s）。
  - 8 個「整條曲線」最近（髮根、1/4、1/2、3/4、髮尾 5 點的距離）：一起走的髮絲。髮根中位距離 3.9 mm。
  - 8 個「中點」最近：經過同一位置的髮絲（可能來自不同髮根）。髮根中位距離 6.5 mm。
  - rel = 鄰居與自己在 5 個點的位移，轉到自己的髮根座標系，單位 cm（15 維）。
- 訓練設定與 bp12b 完全相同（從 bp8 @500、1000 步），只多兩層 kNN block，新層 lr 3e-4（其餘 1e-4）。
  啟動腳本 `data/run_bp15.sh`。
